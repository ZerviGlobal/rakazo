Rakazo vs LobeHub — two shapes of agent platform

Both are running on this host right now. Facts read from both, not from their marketing.

They are not the same product at different maturity. LobeHub is an agent platform: many agents, many conversations each, tools attached as configuration. Rakazo is an agent workspace: each assistant gets a Linux computer and one thread, so it can drive a desktop rather than only call APIs.
LobeHub answers questions. Rakazo does jobs.

The two architectures, side by side

What each is actually good at

Rakazo wins when the work is a job

  • A photographed Thai invoice → read it, do the arithmetic, produce a PDF. Proven: it returned DO-2569-0042.
  • Shell, files, browser, screen — the work that is not an API call.
  • A persistent desktop per space, with installed tools shared by every assistant.
  • Thai UI end to end, with employee-shaped navigation.

LobeHub wins when the work is many specialists

  • 211 agents, each with its own persona, model and tool set — a searchable catalogue.
  • Knowledge bases with vector retrieval: 89 KBs, 559 agent↔KB links.
  • Sharing is built in — workspaces, visibility, groups, market.
  • Topics: many separate conversations per agent, which is what people expect of chat.

What the comparison exposes

Rakazo cannot share one assistant across a department. LobeHub has had workspace_id, visibility and groups all along. This is the gap you asked me to build, and it is the one place LobeHub is plainly ahead.
Rakazo has one conversation per assistant. Thread.botId is @unique, so there is no "topic" concept. One thread per assistant is fine for a single employee and wrong for a team — which is why the shared-assistant design has to change this constraint rather than add a flag.
LobeHub has no computer at all. Not a maturity difference — an architectural one. It answers about a document; Rakazo can open one, convert it, and write the result. For a seat-cover factory that is the whole job.
44 of 211 LobeHub agents have no plugins, and 43 have no enableAgentMode key — exactly the "has tools but won't use them" failure your own platform notes call out as the known one. 3 more have it explicitly false. So the catalogue is bigger than the working catalogue.
