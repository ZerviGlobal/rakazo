1 · Where it actually runs

Only web:5173 and api:3100 are published, both pinned to the tailnet IP in zbox-bind.yml. A bot gets its own network with egress restricted — it is not on rakazo_app. The supervisor replaces a bot container when the desired image differs from info.Image, which is why changing the computer image is disruptive to a live user.

2 · The logic: what happens when you send a message

#StepWhy it is not simpler
1You type Thai and attach a file The file goes as artifactIds — an attachments field does not exist and zod silently drops it
2web → api over /rpcProxied with xfwd so the API sees the real client IP
3api inserts message + task + runStatus starts queued; the run is the unit of work, not the message
4api enqueues run.continueA Graphile job, so the HTTP request returns immediately
5worker leases the run leaseOwner + leaseFence stop two workers running one run twice; a crash resumes instead of duplicating
6worker ensures the bot computer Supervisor finds it by rakazo.botId label and reuses it; replaces only when the desired image differs
7–8model proposes a tool call; the tool runs in the bot container The model never touches ZBOX directly — tools execute inside the sandboxed bot
9loop until doneProgress blocks stream to the UI while this runs, so a long job is visible
10–11blocks stored, reply appears userErrorMessage turns a raw provider blob into readable Thai
run.status: queuedleasedrunningwaiting_input waiting_takeovercompleted failedcancelled

Two of those explain a bot that seems to stall: waiting_input means it called ask_user and is waiting for you; waiting_takeover means it handed computer control to a human. Both are alive, not broken.

4 · The three gaps, drawn in red above

Assistants are per-user, not per-department. Bot carries its own userId and reads filter spaceId AND userId — so two colleagues cannot share one assistant, which is how Zervi actually wants to work.
Tailnet-only and HTTP-only. Reachable at http://100.74.72.109:5173 and nowhere else. Fine for you; not usable by staff.
No Thai font in computer:edge. The bot can read Thai (proven: it returned DO-2569-0042 from an image), but Thai documents it generates render as empty boxes.

Facts read from the running system: ids.ts (RunStatus), rpc.ts (38 namespaces), builtin-tools.ts (tool catalog), docker ps, and the live database — 49 completed, 2 failed, both with their recorded reason. The companion JSON beside this file is the editable structural record.
